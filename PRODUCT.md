# FORGE

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Owner-confirmed primary users are no-code users opening localhost and operating
through GUI. Thai is the default language, with English available. Windows
localhost is mandatory; macOS launchers are requested with platform qualification
reported honestly. Mobile Owner access is mediated by Hermes Agent or OpenClaw.

## Product Purpose

Create, plan, execute, inspect and verify work in one local workspace, with a bot
team, canonical tasks, notebooks, native documents/sheets and generated reports.
Success requires working integrated flows and durable evidence, not placeholder
menus or configuration alone.

## Operating Context

FORGE owns project/task/approval/evidence/release authority. T3 is the default
provider/thread execution owner; AG-UI projects actual state and events. Univer
owns native Office editing; WordCraft/PdfCraft own report generation. Connected
compute, storage, model serving and desktop targets retain explicit scope.

## Capabilities and Constraints

Preserve all Complete Local v3 requirements and subsequent Owner additions.
Assistance Strategy considers connected models, balances quality/cost, starts a
suitable Executor, and uses a larger Asst only for difficult or stalled work.
Mobile work enters Inbox and is approved by the Owner in its originating channel.
DeepSeek Harness informs incremental plugin/context/goal improvements; an optional
backend stays disabled until qualified. No competing planner or task database.
No CA-EWS or other prototype, credential migration, purchase or public hosting.
Main delivery follows the existing release authorization; no push yet.

## Brand Commitments

FORGE name; minimal, beautiful and distinctive app requested by Owner, with an
ambitious presentation. Named VS Code themes with Dark Modern default remain
binding. Landing references supplied by Owner: Orca, T3, Paseo. Impeccable was
explicitly requested to improve design craft. Keep real functionality and content.

## Evidence on Hand

Actual developer screenshots and sanitized verification records in docs/evidence;
worker handoffs distinguish fixtures, actual runtimes, live providers and Home UAT.
No invented customers, testimonials, performance metrics, connectivity or model
quality claims. HOME_UAT_NOT_RUN remains explicit until the Owner runs it.

## Product Principles

- Make the primary workflow usable through GUI.
- Preserve acknowledged work and prove effects with durable receipts/artifacts.
- Treat unknown external outcomes as unknown; never replay effects to recover UI.
- Keep authentication, authorization and scope independent of model-visible tools.
- Expose actionable setup and truthful implementation/qualification limits.
