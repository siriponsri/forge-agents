FORGE

Plan the work. Coordinate agents. Review the evidence.

FORGE is a local-first workspace for taking an idea through planning, execution and delivery. Conversations, agent runs, task dependencies, code, documents and verification evidence stay connected to one project, with explicit Owner approval for plans and controlled actions.

The interface defaults to Thai and supports English. The local core is Apache-2.0; optional remote and team services remain a future direction.

A workspace that follows the work

  • Plan and deliver. Turn a brief into a reviewed Mission, canonical tasks and measurable acceptance criteria. Register actual output files, run reviewed local tests, preview supported static output and produce a verified Delivery Pack.
  • See who is doing what. Switch a team conversation into a Node-Edge Workspace to inspect agents, runs, tools and artifacts. Both views use the same records and existing permission-checked controls.
  • Work in isolated checkouts. Give independent tasks separate Git worktrees, check their actual changes and review the integration queue. The original workspace and its uncommitted work stay under their existing owner.
  • Choose models deliberately. Inspect connected provider catalogs and exact model options. Select Executor, optional Asst and reviewed Strategist handoffs. Assign scoped session roles; a role never grants tools or plan authority.
  • Choose how the team works. The GUI offers Supervisor/Workers, parallel fan-out/fan-in, Router/Specialists, Generator/Verifier, DAG and independent candidates with explicit selection. Existing owners retain execution, checks, budgets and Stop; see the mode contracts.
  • Keep useful knowledge. Search scoped local memory and retain provenance. Central Owner Memory is private until the Owner shares an exact revision with a named project. Editing or revoking that source invalidates the old grant.
  • Create documents and reports. Edit real Univer Docs and Sheets, save and reopen revisions, then generate validated DOCX/PDF from saved report sources.
  • Operate from the same project. Run Python jobs, inspect artifacts, configure compute and serving targets, review MCP permissions and monitor outcomes. Unknown results and unreported costs remain visible as unknown.

Run locally

Development source launcher packages are available for Windows and macOS. Exact source revision, requirements and limitations · SHA-256 checksums. Extract the entire ZIP before starting. These unsigned packages include the launcher and source, including private-runtime setup tools; they do not bundle Node.js, provider accounts or machine runtimes. Native macOS verification is unrun.

Windows is the primary development platform. Install Node.js 24.13+ and Git; local notebook and Python job execution also need Python. The first launch needs internet access to obtain dependencies pinned by the lockfile and build the workbench. This is a source installation.

  1. Clone the complete repository, or extract its complete source archive.
  2. Double-click Start-FORGE.cmd in the repository root.
  3. Wait for readiness and the browser to open. The default address is http://127.0.0.1:4317; the launcher can select another available local port.
  4. Create a project with its own workspace folder, separate from FORGE's source repository. Configure a provider and exact model in project Settings.
  5. Use Stop-FORGE.cmd to stop the service, or Restart-FORGE.cmd to restart it.

Closing the browser does not stop FORGE. Provider sign-in belongs to FORGE's isolated matching T3 runtime; your development application's sessions are not copied into it. API keys use the machine vault and explicit references.

To install and start from a terminal:

git clone https://github.com/siriponsri/forge-agents.git
cd forge-agents
npm ci --include=dev
npm run build
npm start

For an existing clone, preserve local changes before updating. Use git pull --ff-only origin main only when the branch is clean and has not diverged; then start through the launcher so dependencies and the build are checked. See the Thai quickstart for setup, logs and recovery.

Optional private native runtimes and report engines have separate installation and configuration flows in Settings. Their compiled images, fonts and machine credentials are not bundled in Git. Idea to delivery

  1. Write the brief. Define the outcome, inputs, acceptance criteria, dependencies and unresolved decisions. Workflow presets help structure it.
  2. Review the plan. Choose the team and task dependencies, then approve the concrete plan before execution.
  3. Inspect the work. Follow the task's real run and registered output files. Chat and Workspace provide conversation and graph views of the same evidence.
  4. Verify the output. Review the test command and source hashes, run supported local checks and open the immutable static preview.
  5. Accept the delivery. Review QA evidence, record Owner acceptance and build the Delivery Pack with its files, manifest, test results and limitations.

How the system fits together

The main path runs left to right; supporting paths sit below it. Open full size for zoom · PNG alternative · Editable sources and visual credits.

FORGE owns project, plan, task, approval and evidence records. T3 owns provider execution. AG-UI projects state and events into the interface. Executor, Asst, Strategist and scoped session roles use those boundaries; they do not establish a second execution or approval authority. MCP selection does not itself grant permission: Allowed/Ask/Off policies and exact-operation checks apply at dispatch.

Telegram is the first supported mobile bridge channel through Hermes Agent or OpenClaw. New work enters an Inbox, is linked to a reviewed task and requires Owner approval in the originating channel. Live mobile qualification is tracked separately from the bridge's developer fixtures.

Data, credentials and recovery

Windows data defaults to %LOCALAPPDATA%/FORGE/workbench, outside the source checkout. Machine credentials, provider sessions and browser profiles are not portable project data and do not belong in Git.

Use the in-App storage and backup tools with their stated scope. Metadata backups and portable project bundles have different contents; neither should be treated as a copy of machine credentials or installed engines. Restoring older metadata preserves deletion, approval-revocation and execution-deduplication safeguards.

For an interrupted local Python attempt, use explicit Compute reconciliation. FORGE can recover a verified cleanup receipt without executing Python again. Missing or tampered proof remains interrupted. See the local job recovery guide and security policy.
