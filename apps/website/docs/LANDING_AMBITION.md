# FORGE landing — visible orchestration

Design extension dated 26 November 2026. This documents the Owner-authorized
landing redesign. The installed workbench, site routes, inner-page source copy,
bundled assets and the base `style.css` remain in their existing boundaries.

The visitor is a Thai no-code owner evaluating a local AI workspace. The page's
job is to make the connected workflow understandable and lead to the existing
source setup guide. English remains available by URL. The visual voice is
confident, industrial and purposeful: large upright Manrope, readable IBM Plex
Sans Thai, exact orange `#f97316`, secondary yellow `#f2c94c` and gray `#8b9199`.
Neither secondary color carries semantic status or small explanatory text.

## Composition and interaction

The original page's headline/right-hand explanation now has stronger scale and
a tighter hierarchy. A compact index leads to formations or the real workbench.
A dark formation plane interrupts the light page rather than repeating feature
cards. Product evidence follows as a large genuine capture. Open workflow rows,
the existing ownership explorer, capability ledger and setup invitation retain
the original information architecture and source/release destinations.

The central move is a six-mode strategy explorer. Each choice changes the lead,
allocation, aggregation and boundary explanation. Native pressed buttons support
Left/Right, Home/End, wrapping and focus retention without a scroll jump. The
diagram becomes a two-column reading sequence on phones; labels remain actual
HTML text rather than a scaled-down desktop image. A screen-reader caption
describes the route, including sequential dependencies and selected alternatives.

Four step controls explain scope, allocation, inspection and retained evidence.
Play is opt-in and finite. A transform-only time indicator shows when the next
explanation will appear. Pause, mode changes, manual step selection, leaving the
viewport, hiding the document and enabling reduced motion stop playback. Reduced
motion gives a manual Next step button and removes spatial transitions. There
are no entrance cascades, ambient loops, parallax, fake terminals or fake chrome.

The explorer is expressly labelled **illustrative / in development / not a live
run**. All six modes are described as active development on an unpublished branch.
It never states that the public d928e9c checkpoint contains the new modes, that a
mode executed successfully, or that a provider/model has a quality advantage.

## System and preservation

`src/tokens.css` contains the landing's semantic extension. It consumes the site's
existing ink, muted, accent, paper and line roles and adds named dark-diagram
roles. `src/landing.css` scopes the redesign to `.landing` and the new strategy
component; `main.tsx` imports both after the unchanged existing CSS import.
`html/body overflow-x: clip` is the only global layout safety addition.
No package, lockfile, font, public asset, source snapshot or backend was changed.

The genuine 1440×1000 product screenshot remains byte-for-byte unchanged, with
its original baseline/date/fixture disclosure and full-resolution link. It is
not presented as evidence for six-mode execution or later product integrations.
Font/icon/React/Radix licenses remain bundled. No external runtime, font, analytics
or embedded service is introduced. Release links continue through the existing
validated metadata; absent installers are not replaced with fake downloads.

The 26 November checked-in anonymous publication record is the authority:
public main d928e9c, no GitHub releases. Later implementation is unpublished.
Windows source setup, native desktop/provider qualification boundaries,
macOS native NOT_RUN, report-engine restrictions and HOME_UAT_NOT_RUN survive in
their existing routes and capability text.
